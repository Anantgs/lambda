# Kafka Consumer UI

A beautiful web-based Kafka consumer application that displays real-time message consumption, statistics, and monitoring. Perfect companion to the Kafka Producer UI.

## Features

- **Beautiful Modern UI**: Sleek, responsive web interface with Bootstrap styling and animations
- **Real-time Monitoring**: Live message consumption with auto-refresh
- **Statistics Dashboard**: Track consumption rate, event types, and performance metrics
- **Message Display**: View recent messages with detailed metadata
- **Event Type Analysis**: Visualize distribution of different event types
- **Consumer Group Support**: Configure custom consumer group IDs
- **EC2 Ready**: Dockerized for easy deployment on EC2 instances

## Architecture

The consumer UI consists of:

- **Flask Web Application**: Provides the web interface and API endpoints
- **Kafka Consumer**: Uses kafka-python to consume messages from topics
- **Real-time Statistics**: Tracks consumption metrics and message patterns
- **Message Buffer**: Maintains recent message history for display

## Prerequisites

- Python 3.9+
- Docker (for containerized deployment)
- Access to a Kafka cluster

## Local Installation and Setup

1. Navigate to the consumer directory:
   ```
   cd kafka-consumer-ui
   ```

2. Install Python dependencies:
   ```
   pip install -r requirements.txt
   ```

3. Run the application:
   ```
   python app.py
   ```

4. Open your browser and go to `http://localhost:5001`

## Deployment on EC2

1. Ensure Docker is installed on your EC2 instance:
   ```
   sudo yum update -y
   sudo yum install -y docker
   sudo systemctl start docker
   sudo systemctl enable docker
   ```

2. Build the Docker image:
   ```
   cd kafka-consumer-ui
   docker build -t kafka-consumer-ui .
   ```

3. Run the container:
   ```
   docker run -d -p 5001:5001 kafka-consumer-ui
   ```

4. Access the UI at `http://your-ec2-public-ip:5001`

## Configuration

- **Bootstrap Servers**: Comma-separated list of Kafka brokers
- **Topic Name**: The Kafka topic to consume from
- **Consumer Group ID**: Unique identifier for the consumer group (optional)

## Features Overview

### Real-time Statistics
- **Total Messages Consumed**: Running count of processed messages
- **Consumption Rate**: Messages per second (updated every 5 seconds)
- **Runtime**: How long the consumer has been running
- **Event Types**: Count of different event types encountered

### Message Display
- **Recent Messages**: Last 10 messages with full details
- **Message Metadata**: ID, timestamp, event type, user ID, partition, offset
- **Color-coded Events**: Different colors for different event types
- **Auto-scroll**: Latest messages always visible

### Event Analysis
- **Type Distribution**: Bar chart of event types
- **Real-time Updates**: Statistics update as messages are consumed

## Usage

1. Enter your Kafka configuration in the web form
2. Click "Start Consumer" to begin consuming messages
3. Monitor the real-time statistics and message flow
4. View detailed message information in the recent messages panel
5. Click "Stop Consumer" to halt consumption

## API Endpoints

- `GET /`: Main web interface
- `GET /api/stats`: JSON API for current statistics

## Integration with Producer

This consumer UI is designed to work seamlessly with the Kafka Producer UI:

1. **Start Producer**: Use the producer UI to send test messages
2. **Start Consumer**: Use this consumer UI to view the messages
3. **Monitor Flow**: Watch real-time statistics on both ends
4. **Test Scenarios**: Validate message formats and processing logic

## Message Format

The consumer expects JSON messages in the format generated by the producer:

```json
{
  "id": 1,
  "timestamp": "2026-01-23T10:30:00.123456",
  "event_type": "user_login",
  "user_id": 1234,
  "message": "Event 1 occurred",
  "details": {
    "ip_address": "192.168.1.100",
    "user_agent": "Mozilla/5.0",
    "session_id": "abc123def456"
  }
}
```

## Performance Considerations

- **Memory Usage**: Maintains buffer of last 100 messages
- **Threading**: Consumer runs in background thread
- **Auto-refresh**: UI refreshes every 5 seconds when active
- **Scalability**: Single consumer instance (scale horizontally with multiple instances)

## Troubleshooting

- **Connection Issues**: Verify bootstrap server URLs and ports
- **No Messages**: Check if producer is running and topic exists
- **Performance**: Monitor consumption rate vs producer rate
- **Memory**: Restart if message buffer grows too large

## Security Considerations

- For production, consider adding authentication
- Limit access to consumer UI in production environments
- Use HTTPS for secure access
- Monitor for unauthorized access attempts
